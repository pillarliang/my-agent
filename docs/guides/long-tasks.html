长任务处理与跨会话知识复用

1. 核心本质差异：长任务 vs 跨会话知识复用

在构建 Agent Harness 时，初学者极易将“长任务处理”与“知识复用”混为一谈。两者针对的其实是两个完全不同的技术维度：

对比维度 长任务支撑（Task-Level） 跨会话知识复用（Session-Level）
核心问题 单次任务执行步数多（如 20 步）、单步工具输出极大（如读数 MB 日志），导致模型上下文瞬间被撑爆或早期目标被裁剪丢失。 会话 A 结束并开启全新的会话 B 后，会话 B 如何记住项目的编码规范、工具命令偏好或用户习惯。
作用范围 单个任务内部的多次模型迭代循环。 跨越多个独立会话的全局或项目级持久化存储。
主要手段 大输出本地暂存与首尾预览（Offloading）、历史交互块结构化压缩（Compaction）、任务预算硬裁剪。 项目记忆文件（MEMORY.md）、长期记忆读写管道、向量检索或分层 Memory Store。
实践主线 阶段 6：长任务支撑：大输出暂存与历史摘要 阶段 5：用 Memory 跨会话复用项目知识
底层原理 Context Manager：组织本次发给模型的内容 Memory：选择跨会话保留的知识

2. 快速查阅指引

根据你正在排查的实际工程痛点，直接查阅对应模块：

  • 遇到工具返回内容太大撑爆窗口：参阅 阶段 6 中的大输出本地暂存机制，以及 Context 模块的大段结果另存与预览方案。
  • 遇到任务步数太多导致模型忘记早期目标：参阅 阶段 6 中的历史结构化摘要机制。
  • 遇到新会话记不住项目规则与依赖命令：参阅 阶段 5 项目记忆实现，以及 Memory 模块的增删改查机制。
  • 查阅最原始的单会话完整执行记录：参阅 Session / State：管理会话与执行记录。
