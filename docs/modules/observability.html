模块原理 · 运行时透视与全链路追踪

Observability：运行时全链路观测与追踪

1. 问题起点：为什么传统 APM 无法满足 Agent 的观测需求？

传统后端服务（如 Web API）的调用链路是高度确定性的：网关接收请求 → 路由至 Controller → 查询数据库 → 序列化返回。但在 Agent 运行过程中，情况发生了根本性变化：

  • 动态决策循环：单次任务不是线性的，而是经历多次 模型思考 → 工具调用 → 回执观察 → 再次模型决策 的自主闭环（ReAct）。
  • 非结构化上下文与 Token 膨胀：每一次模型调用传入的 Prompt 都在动态变化，Token 消耗随轮数递增，普通的 HTTP 状态码无法反映推理内容与成本。
  • 工具与策略拦截：工具参数不合法、Policy 拒绝执行等情况属于系统的预期保护行为，不能简单粗暴地当作服务器内部 500 崩溃处理。

如果只依赖标准日志或传统监控，排查问题时会陷入困境：只知道耗时很长，但不知道模型哪一步陷入了犹豫；只知道花费了高昂 Token，但不知道是哪条历史消息撑爆了上下文。

期望达到的效果：

  • 全调用链路可视化：单次任务的完整生命周期通过统一的 Trace 树呈现，清晰还原模型思考、工具调用与回执嵌套关系。
  • Token 与成本精准审计：精确记录每次模型调用的 Prompt Token 与 Completion Token，自动核算任务开销与延迟分布。
  • 线上故障可回溯下钻：一键根据 Session ID 还原当时发给模型的完整上下文，复现并定位 Badcase 诱因。
  • 零主路径侵入：观测数据采用异步通道旁路收集，即使监控服务端网络抖动，也绝不阻断 Agent 的执行流。

2. 核心抽象：Trace、Generation、Span 与 Score

为满足大语言模型与 Agent 的特有结构，现代观测标准（如 OpenTelemetry GenAI 规范与 Langfuse 模型）统一抽象出四层核心对象：

  1. Trace（根追踪）：
    • 代表一次完整的用户任务或执行生命周期（Agent Run）。
    • 承载任务全局属性：唯一的 trace_id、用户所属会话 session_id、用户标识 user_id、初始 Prompt 输入、最终产物与总耗时。
  2. Generation（模型生成节点）：
    • 专门用于描述向大模型发起的补全调用。
    • 记录关键元数据：使用的模型名称与版本（如 gpt-4o、claude-3-5-sonnet）、输入 Messages 列表、模型最终回复、Token 消耗细则（Prompt / Completion Tokens）与模型首字时延（TTFT）。
  3. Span（工具与系统动作片段）：
    • 记录 Agent 内部的关键逻辑步骤与工具执行。
    • 常见类型包括：tool_call（真实工具执行及出入参）、policy_check（动作鉴权结果）、context_compaction（上下文裁剪与摘要耗时）。每个 Span 记录起止时间戳、状态码与执行异常。
  4. Score（质量与反馈打分）：
    • 附加在 Trace 或 Generation 上的离散/连续评分。
    • 数据来源可以是用户的直接点赞/点踩反馈、线上安全规则检测、或轻量级质量拦截信号。

3. 架构与工业界实践：以 Langfuse 为代表的观测体系

在开源生态中，Langfuse 是目前针对 LLM 与 Agent 支持最完善、社区最活跃的开源观测平台之一。它支持私有化 Docker 极速部署，兼容 OpenTelemetry 语义协议，并提供了针对 Agent 调用树的高性能分析看板。

4. Agent 观测落地的三项工程守则

  • 1. 异步非阻塞上报（Asynchronous & Non-blocking）：
    • Agent 本身的模型推理与工具执行往往耗时数秒，观测上报必须通过后台线程池或异步队列批处理发送。
    • 任何网络超时、重试或观测服务端宕机，绝不能向 Agent 主逻辑抛出异常，必须保障核心任务不受任何干扰。
  • 2. 敏感数据前置脱敏（Data Sanitization）：
    • Agent 工具在读取本地环境变量、配置文件或物理代码时，可能携带数据库密码、用户私钥或内部凭证。
    • 在进入 Span 或 Generation 之前，必须在客户端配置正则脱敏过滤器（Scrubber），防止敏感机密泄漏至观测平台。
  • 3. 跨轮会话的 Session 统一聚合：
    • 在多轮连续追问中，每一次用户提问会触发一次独立的 Agent Run（生成独立的 trace_id）。
    • 系统必须将它们统一归属到同一个 session_id 下，以便平台能够按对话主线追踪上下文膨胀趋势与累积计费。

5. 实战集成：在 Agent Runner 中无感嵌入观测埋点

在 Agent Harness 内部，观测埋点可以通过装饰器或回调方式注入，保持核心执行逻辑纯粹：

telemetry_runner.py
from langfuse import Langfuse

class ObservabilityRunner:
    def __init__(self, inner_runner):
        self.inner = inner_runner
        self.langfuse = Langfuse()

    def run_task(self, session_id: str, prompt: str):
        # 1. 开启顶层 Trace 容器
        trace = self.langfuse.trace(
            name="AgentRun",
            session_id=session_id,
            input={"prompt": prompt}
        )

        try:
            # 2. 挂载模型生成与工具执行钩子
            result = self.inner.run_task(
                session_id=session_id,
                prompt=prompt,
                on_model_call=lambda req, resp: trace.generation(
                    name="ModelCall",
                    model=req.model,
                    input=req.messages,
                    output=resp.content,
                    usage={"prompt_tokens": resp.prompt_tokens, "completion_tokens": resp.completion_tokens}
                ),
                on_tool_execute=lambda call_id, name, args, output: trace.span(
                    name=f"tool:{name}",
                    input=args,
                    output=output
                )
            )

            # 3. 记录任务最终交付物
            trace.update(output={"status": result.status, "answer": result.final_answer})
            return result

        except Exception as exc:
            trace.update(output={"error": str(exc)}, level="ERROR")
            raise
        finally:
            # 4. 后台异步刷盘上报
            self.langfuse.flush()

6. 本项目当前实现与演进路线

  • 已实现（阶段 0–5）：
    • 运行期控制台输出：Runner 实时在终端打印单步执行状态、工具调用名称与真实回执，提供直观的本地步骤视图。
    • Token 精准统计：ModelResponse 结构严格保存每次调用模型服务返回的用量字段（Prompt Tokens、Completion Tokens），由 Runner 累加汇总至 RunResult。
    • 持久化执行日志：会话记录层将用户提问、模型响应、工具调用参数与回执顺序写入单会话 JSONL 文件（详见 State 模块）。
  • 后续演进路线：
    • 通过非侵入式 Adapter 接入 Langfuse Python SDK，将现有的控制台输出与 JSONL 事件自动映射为 Trace 拓扑。
    • 在长对话和复杂工具调用场景下，通过 Langfuse 看板实时观测 Token 增长瓶颈与耗时切片分布。
