Quality：观测与评测

1. 解决什么问题，必须保证什么

观测回答“运行中发生了什么”，评测回答“在指定任务和标准下表现怎样”。例如模型读取 notes.txt 后说“已完成”，观测能告诉我们调用了什么工具、返回了什么；评测还要核对回答或产物是否满足任务要求。工具成功、循环正常结束和任务合格不能合并成一个状态。

观测应关联运行、步骤和实际证据；评测要保存任务、输入与标准，区分可复现的程序检查和真实模型的任务表现。通用日志或漂亮的调用图都不能替代明确的检查标准。

2. 与相关模块怎样交互

运行流程记录实际调用和结果，观测模块读取这些记录。Runner 的过程事件、Model 返回的用量和错误、Tools 的真实回执经记录层保存后，可以交给观测查询或导出；观测模块不应为了补齐图表而重新执行工具。普通观测导出失败如何处理需要约定，它不同于关键执行记录尚未保存。

评测由测试或实验入口发起。入口固定任务和资料，让应用运行后把结果与真实产物交给检查器；检查器返回结论、检查范围和证据。若需要把反馈交回 Runner 自动修复，还必须另行约定修复预算与权限，观测或评测本身不自动拥有重启执行的权力。

按需阅读：后续观测与评测方案

3. 观测有哪些方案

这里比较观测记录怎样关联、存放和查看；这些方式不替代任务评测。当前只有控制台进度和真实回执，没有持久事件、独立导出、汇总分析或观测模块。

A. 结构化本地事件

JSONL 或 SQLite 按顺序记录运行中的关键步骤，保存固定 ID 和必要元数据，正文单独存储。它依赖少、便于本地学习；代价是跨进程关联、聚合、查询和可视化需要继续建设。

注意区分用于观测的日志与用于恢复的执行记录：可能因采样而不完整的日志，不能代替恢复所需的完整执行记录。两者的关系见 State。

B. Trace、Span 和指标

一个 Trace 关联整段请求或工作流，Span 表示模型、工具、子任务等操作，记录父子关系、起止时间和状态。OpenTelemetry Trace 规范提供这些基本结构。

它适合跨服务定位耗时和失败，代价是在服务间传递追踪 ID、采样、导出和维护字段格式。Token 用量、工具调用次数和排队时间可以作为指标；不应把原始文件全文和密钥直接放入指标标签，既会泄露内容，也会产生大量难以汇总的标签值。

C. 专用 Agent 观测平台

通过适配器导出调用树、Prompt 版本和评测记录，复用平台界面与数据集管理。它能减少展示开发，也带来数据存放、访问范围、费用和平台耦合。

不论使用哪种平台，本地运行 ID、任务版本和产物证据都应可关联。平台上出现一条绿色调用记录，不代表业务检查覆盖了全部要求。

4. 真实实现怎样组织观测

OpenAI Agents SDK，官方文档。 观测说明描述模型、工具、Handoff、Guardrail 和自定义 Span 的运行轨迹。可借鉴的是围绕真实操作建立调用树，而不是只保存最终 Prompt 和答案。

AgentScope Java，指定版本的官方文档。 Session Log 将执行记录、用户可读历史与事件订阅关联。可借鉴的是让页面刷新后能根据运行 ID 补读，而不完全依赖瞬时回调。

OpenTelemetry，规范现状。 原 GenAI 页面已说明迁移至独立语义约定仓库。接入时应固定所采用的版本并验证映射；当前 Learn Agent 尚未按这些约定接入观测系统。

5. 测试和评测怎样分层

本地组件测试直接使用参数、文件和数据库，检查解析、权限、上下文选择与存储。不依赖模型的行为直接用程序检查；输入选择或事务正确不代表模型任务能力。

协议检查可使用实际 SDK 连接本机固定响应服务，稳定验证调用关联、拒答、截断和错误处理；当前测试采用这一方式。真实供应商端点的行为需另行验证，并记录请求用量和未覆盖分支。本机固定响应不能证明远端模型表现。

任务评测固定任务、工作区、模型与检查器，记录检查结果、工具路径、用量和时间。它衡量整体决策表现，重要结论应重复运行并报告样本数，不能拿一次成功当作长期成功率。当前未实现批量真实任务评测。

6. 本项目当前选择与未实现范围

截至阶段 2：控制台进度与本地接口行为检查。Runner 打印进度，ModelResponse 保留供应商报告的用量；pytest 检查文件、权限与协议。当前没有持久事件、独立 Quality 服务或统一任务评分。

选择本地记录和可重复的程序检查，是为了先确认各模块的接口行为符合约定；实现和验证入口见阶段 3 检查与验证范围。当前没有独立的结果检查模块，Policy 的拒绝也不是产物质量评价。

未实现：Trace 导出、指标聚合、观测平台接入、批量真实任务评测、模型评分和自动修复。后续可按阶段 4 固定任务、资料与评价标准，选择确定性检查、人工评价或模型辅助评价；分别权衡覆盖范围、人工成本与评分偏差。
