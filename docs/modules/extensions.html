模块原理与方案

Extensions：接入 Skills、Hooks 和外部工具

1. 实现原理：查找扩展、配置接入和实际执行分开

扩展加载：方法、回调与工具分别接入

加载能力不等于授予执行权限。

Skill 主要提供可复用方法；Hook 在运行开始、工具调用前后等时刻触发；中间件包裹模型或工具调用，可能改写请求或结果；MCP 连接外部工具、资源与 Prompt；Plugin 管理一组内容的安装、版本和分发。

发现文件不等于执行脚本，加载方法也不等于增加权限。扩展可以改变模型看见的内容或程序走过的路径，因此需要明确每类接口的影响范围。

2. 与相关模块怎样交互

应用选择扩展，加载器将不同扩展接到相应模块。方法资料送给 Context Manager 按需选择；在特定运行步骤触发的回调接到 Runner 的指定执行步骤；外部工具定义和调用由 Tools 适配。它们不是同一种“插件函数”，不能因为一起安装就获得相同权限。

扩展改变工具参数后必须重新校验和授权；观测回调只能在约定范围读取信息。包缺失、版本不兼容或方法加载失败应报告给发起方；普通观测失败可按明确策略处理，用于阻止动作的控制回调失败则应拒绝执行。加载版本与触发证据可以进入 State，但记录不代替权限决定。

方案按接入对象分别比较：方法可以常驻、按需加载或检索后加载；Hook 可以进程内或进程外；中间件用于包裹调用；MCP 用于外部能力通信；Plugin 管安装和版本。它们可以组合，当前尚未选定动态扩展体系。

3. Skills 有哪些加载方案

A. 全量正文常驻

启动时读全部方法，将正文加入每轮输入。实现直接，适合极少、很短且固定的方法。代价是输入随方法库增长，与任务无关的内容和冲突也会增加。

B. 元数据发现，正文按需加载

先读取名称和用途，匹配任务或由用户选择后，再在长度限制内读取正文；引用资料和脚本继续按需访问。需要索引、选择规则、路径检查和加载记录。

它能减少常驻内容，也方便说明某个方法为何激活。代价是误触发和遗漏，且正文仍可能很大。应记录内容哈希与版本，让同一次 Run 使用明确的材料。

C. 检索驱动的方法库

先按任务检索候选，再比较适用条件、版本与依赖。适合大型方法库，但需要检查能否找到相关方法、排序是否合理，并持续维护索引和方法版本；高度相似的方法也可能相互矛盾。

Agent Skills 规范定义方法目录、元数据与正文，宿主决定加载和执行行为。某个字段出现在规范里，不代表每个宿主采用相同授权规则。

4. Hooks 和中间件怎样实现

进程内回调

程序在 run.start、model.before、tool.before 或 tool.after 等时刻调用已注册的函数。它类型清楚、开销低，适合可信内置逻辑；代价是共享内存和权限，阻塞会影响主流程。

进程外事件协议

通过 stdin 传事件 JSON，stdout 返回约定的控制结果，stderr 写诊断日志。它便于输出限额、超时和进程终止，也需要接口版本、各退出码的含义与子进程清理。

不同事件应有不同能力。例如观测事件只读取元数据，工具前事件可以拒绝调用。若允许改写参数，应重新解析、校验和授权，不能先批准旧参数再执行新参数。

包裹调用的中间件

中间件接收请求和下一层处理函数，可以修改输入、重试或观察结果。嵌套通常形成“外层前处理 → 内层前处理 → 实际调用 → 内层后处理 → 外层后处理”，调用顺序会直接影响最终结果。

它适合组合日志、重试、输入转换等通用功能，代价是调用链不再直观。一个重试中间件包住工具执行，可能重复副作用；如果摘要中间件先计数，之后才加入工具定义，就可能低估输入大小。需要固定顺序并检查真实输入。

扩展点 适合什么 收益 主要代价
进程内回调 可信、轻量事件逻辑 简单、低延迟 共享内存、权限与故障影响
进程外 Hook 外部脚本和独立超时 接口与进程可分离 协议、清理与部署
中间件 请求转换和组合控制 复用多个调用都需要的功能 调用顺序和重试规则更复杂

普通观测导出失败可以按明确策略降级；用于阻止未授权动作的控制逻辑失败时应拒绝执行。Hook 返回继续，也不能扩大上层强制授权范围。

5. MCP 应接在哪里

MCP：通过适配器复用工具执行流程

执行后端设计 · 当前尚未接入 MCP。

先协商能力并发现工具，把外部定义转换成内部 ToolSpec，在本次 Run 中固定使用同一版本。调用仍经过参数校验、权限检查、预算检查和结果处理；连接失效或 Schema 变化时应明确处理，不能凭旧定义继续猜测。

stdio 服务器通常是本地子进程，需要限定环境变量和生命周期；远程 HTTP 服务器需要认证、超时与连接管理。外部元数据可以帮助展示，不能独自证明真实效果是只读。

MCP 2025-11-25 架构将连接和能力放在 Client / Server，授权与协调留在 Host。业务副作用、幂等、恢复和验收仍需要自己的执行协议。

6. 真实实现可以借鉴什么

Deep Agents，源码核对。 SkillsMiddleware 将发现与模型请求处理分开；graph.py 装配中间件栈。可借鉴的是明确注册位置与生命周期，而不是让所有模块各自扫描目录。

Claude Code，官方文档。 Hooks 说明定义工具前后等事件，以及回调可以返回的有限几种决定，工具前事件发生在模型产生参数之后。它说明事件输入与回调允许返回的结果需要分别定义；具体事件能力应按对应版本核对，不能把所有 Hook 都视为任意控制点。

pi，指定版本的源码。 压缩实现在压缩前后提供扩展回调。可以借鉴的是只允许扩展替换明确的一步处理逻辑，而非一开始允许插件替换整个状态机。

AgentScope Java，指定版本的官方文档。 Skill 装配提供工作区和仓库来源，展示读取资料与配置运行组件的另一种组织方式。本项目无需为第一个保存在本地文件中的方法库立即实现远程仓库。

8. 本项目当前选择与未实现范围

截至阶段 3A：仅有代码中显式注册的本地工具。应用选择工具注册项，ToolRegistry 注册普通函数，新增 count_lines 可沿用相同调用与权限流程，见阶段 1。这验证了新增工具的接入方式，但不是动态插件加载系统。

未实现：Skill 目录发现、方法正文按需注入、Hook、中间件、MCP 客户端和 Plugin 安装管理。当前也没有选定它们的加载方案；本章图示和练习都是未来设计。编写本项目时使用的外部开发助手能力，不代表本项目运行时已经具备同名功能。

后续先用一个真实方法或外部工具验证需求，再按阶段 6 的扩展方向决定是否建设发现、版本与生命周期管理。

9. 后续练习：按需加载与外部工具接入

读取真实方法文件的元数据，由用户选择后才在长度限制内加载正文，不自动执行正文中引用的脚本。检查未激活正文不进入模型输入、版本可追溯、路径逃逸和超大正文被拒绝。

随后接一个真正只读的本地 MCP 服务，检查断连、工具定义变化和超大结果；不模拟模型返回。最后核对扩展没有获得未授予的写能力，观测日志也没有被当作授权来源。
