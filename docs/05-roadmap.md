# 05. 从 MVP 到可恢复系统

路线图按能力逐步推进。每次先选择一项主要改进，写出验收条件，再修改实现和测试；这样可以看清收益来自哪里，也更容易定位新引入的问题。

## 阶段 0：读懂并运行 MVP（已实现）

学习：Session、Run、Step、Context、ToolCall 和 ToolResult。

**实践方式：** 通过 Web UI 或 CLI 运行一次真实读取和报告任务，查看事件与产物；再去掉写授权、设置 `--max-steps 1`，观察权限和预算如何约束模型提出的动作。

**验收条件：** 能根据实际事件解释各次模型输入增加了什么，找到模型提出动作、程序执行工具和独立验证产物的位置。模型路径可能变化，但每一步都要有可检查的记录。

## 阶段 1：建立真实模型基线（首轮三个案例已完成）

学习：模型协议、工具 Schema、响应状态和用量。

**实践方式：** 本机已配置 DashScope，默认模型 `qwen3.8-flash` 已通过一次读取工具与最终回答验证。首轮三个案例已通过并保存[评测摘要](../evals/results/qwen3.8-flash-2026-10-18.json)，下一步扩大样本和重复次数，再比较模型或工具改动。

**验收条件：** 三个真实案例都得到可解释结果，认证与输出截断能通过真实接口验证，未稳定触发的限流和异常要明确记录。单次任务成功还不足以说明长期质量，需要保存模型配置、样本与失败情况。

## 阶段 2：改进工具与验证（后续）

学习：有界搜索、分页、内容哈希和产物证据。

**实践方式：** 先实现 `search_text` 练习有界检索，再增加带预期哈希的精确替换工具；同时增强检查器，将本次调用回执与最终文件哈希关联起来。

**验收条件：** 文件被外部修改时编辑会被拒绝，旧文件无法冒充本次新产物，超大结果也有明确截断标记和补读路径。

## 阶段 3：上下文压缩（后续）

学习：完整块、输入容量、摘要来源和约束召回。

**实践方式：** 增加匹配模型的计数器，再实现“旧摘要 + 最近完整块 + 当前执行链”的输入策略，并为摘要维护来源哈希与版本。

**验收条件：** 长会话中的关键约束和具体数值能够恢复，调用与结果配对保持完整。比较质量与总成本时，应包含额外摘要调用的费用。

## 阶段 4：用户可控的长期记忆（后续）

学习：作用域、来源、版本、过期和撤销。

**实践方式：** 先实现显式的 `remember / recall / forget`，用关键词检索建立可检查的读取路径，再根据实际召回问题决定是否需要向量索引。

**验收条件：** 新会话能复用有效知识，其他项目无法越权读取，遗忘条目不会由旧来源自动重新生成，而且记忆不能改变工具授权。

## 阶段 5：可靠恢复（后续）

学习：检查点、逻辑调用、尝试身份、回执与未知状态。

**实践方式：** 先恢复只读动作，增加故障注入与版本兼容检查，随后再实现写动作的幂等和对账协议。每一步都应能解释崩溃前后哪些效果已确认、哪些仍然未知。

**验收条件：** 各关键边界的崩溃不会导致恢复时重复副作用；效果无法确认时停止并保留 `unknown`，继续执行前重新检查权限与外部前置条件。

## 阶段 6：执行隔离与扩展（后续）

学习：能力授权、进程监督、沙箱和扩展信任。

**实践方式：** 增加独立执行端口与 Worker，先加载不含脚本的 Skill，再接只读 MCP 工具，最后才考虑 Shell、Hooks 和插件安装。

**验收条件：** 恶意文件和扩展无法扩大工作区或网络授权，超时可以终止 Worker 并回收子进程，未知效果与权限撤销都有明确处理方式。

## 阶段 7：Graph、调度与多 Agent（后续）

学习：父子预算、邮箱、任务领取和等待事件。

**实践方式：** 先把只读子 Agent 包装成工具，再实现稳定工作流和外部事件唤醒。有实际的持续沟通需求后，才引入子会话、邮箱或共享任务板。

**验收条件：** 父取消能够传播，子预算不能绕过总上限，重复事件不会重复启动任务，无变化时不会持续调用模型。与单 Agent 基线比较后，质量收益应足以抵消新增成本和复杂性。

## 推荐的第一次扩展

第一次扩展建议选择阶段 2 的 `search_text`，同时练习工具设计、权限、结果限额和模型反馈。完成后，你就有了真实的大结果问题，可以据此评测阶段 3 的 Context 改进。

在尚未理解上下文和状态边界时，多 Agent 与自动记忆提取会增加定位问题的难度。可以先把一个完整任务做稳，再逐步扩展它的能力和运行方式。
