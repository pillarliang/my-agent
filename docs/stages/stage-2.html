阶段 2：用 Policy 控制动作权限

1. 本轮目标：保存摘要，禁止覆盖

已有 Agent 能调用工具读写文件。本轮增加权限检查：允许保存新文件，保留已有文件。完成标准是覆盖请求被 Policy 拒绝，原文件内容未变。

Policy 通用教程讲设计原则与可选方案。本章只讲本项目选用的实现；summary.txt 是验证用的示例名，不是通用入口的固定输出。

2. 当前选择，以及选择理由

  • 动作从哪里来：工具注册时声明所需权限和路径参数名，由共享代码生成本次动作。现有文件工具能复用 read、list、write，不必为每个工具写动作描述函数。
  • 规则怎样判断：Policy 对象保存权限开关和可选的文件名单，evaluate() 用条件分支判断。当前规则少，这种实现便于沿代码阅读，暂不引入配置规则语言或独立策略服务。
  • 在哪里控制执行：ToolRegistry.execute() 统一检查，拒绝就返回，允许才调用注册的函数。普通函数只负责实际操作，新增工具复用已有权限时不改注册表或 Runner。

这是本项目当前采用的方案组合。通用原则要求拒绝能阻止实际操作，并不要求所有 Agent 都采用这些类名、注册方式或判断位置。

3. 按一次调用阅读当前代码

3.1 函数、类与权限数据怎样连接

Policy 是保存规则并实现判断的类，PolicyEvaluator 是注册表依赖的协议。prepare_action() 与 write_file() 是普通函数。ActionRequest、PolicyDecision、ToolCall 和 ToolResult 是数据类，分别传递动作、决定、调用与回执。ToolDefinition 保存所需权限，不保存授权结果。

3.2 一次覆盖请求的调用顺序

  1. main() 创建允许新建、禁止覆盖的 Policy；run_task() 将它与工作目录传给工具注册表。这是初始化配置。
  2. 写入工具注册项声明 permission="write"、path_parameter="path"。它表示需要写入权限，具体文件名来自本次调用，不代表已经获准。
  3. prepare_action() 取出已校验的路径，检查目标：不存在是 create，已有普通文件是 overwrite。它返回 ActionRequest，此时没有写文件。
  4. Policy.evaluate() 按程序配置返回 PolicyDecision。本例的覆盖请求得到 allowed=False，原因是“禁止覆盖已有文件”。
  5. ToolRegistry.execute() 返回带原调用 ID 的 policy_denied 回执，不调用 write_file()。获准时才执行；Runner 接收回执并交给下一轮模型请求。

当前接口约定是 evaluate(ActionRequest) → PolicyDecision。执行函数收到已校验的参数、工作目录和获准动作，不接收 Policy。替换权限判断的实现，不必改变这条交互。

3.3 规则与拒绝结果存在哪里

Policy 的权限开关和文件名单是应用创建的内存配置，当前没有权限规则表、审批表或独立的授权日志表。实验入口 examples.policy_no_overwrite.main() 在临时目录中直接创建注册表并两次调用 execute()，不请求模型、不创建 SessionStore。

通用 CLI 则通过 run_task() 执行 Agent：模型若请求覆盖，policy_denied 作为 ToolResult 保存到 3A 的 messages.message，同时记录 tool_returned 事件；没有额外的 Policy 专用事件。关联的 run_id、step 和 JSON 中的 call_id 可用来定位这次拒绝，字段见 数据库表结构。

4. 运行禁止覆盖实验

通过真实工具先新建、再请求覆盖；不调用模型
uv run python -m examples.policy_no_overwrite

预期：第二次返回 policy_denied，原因是“禁止覆盖已有文件”，文件仍为“原内容”。实验源码走的工具执行路径与 Runner 相同。

5. 检查结果与当前边界

真实临时文件与本机 SDK 协议，不请求外部模型
uv run pytest tests/test_policy.py tests/test_tools.py tests/test_application.py

权限测试确认首次动作是 create、再次是 overwrite，且拒绝后原文件未变。工具测试确认新注册的普通函数也经过统一检查，拒绝后函数不会运行。

本阶段完成权限判断与拒绝执行。声明来自可信工具代码，不能隔离故意违规的 Python 函数；复杂规则、人工审批与操作系统沙箱均未实现。

当前文件工具的执行限制

获准新建后仍使用独占创建；若另一个请求抢先创建目标，返回 file_exists，不改为覆盖。写入不通过符号链接访问文件，父目录须存在，正文最多 16,000 个 UTF-8 字节，当前支持 macOS / Linux。write_incomplete 表示可能留下部分文件，程序错误直接报错。
