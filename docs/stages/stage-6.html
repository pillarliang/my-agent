阶段 6：按需求增加入口、扩展与编排

以稳定运行的单 Agent 版本为基础，选择一项实际需要的扩展。

1. 应用入口

1.1 已有入口、函数与候选扩展的关系

当前入口只有 Agent CLI：main() 负责参数、会话和结果展示，执行通过 run_task() 调用 run_agent()，查询则直接调用 inspect_session()。已有类及其初始化关系见 3A 关系图。

1.2 以新增 HTTP 入口为例说明未来流程

  1. HTTP 入口接收任务与会话 ID，检查输入；未给 ID 时创建会话，给定 ID 时核对工作目录，并沿用调用方获准的配置。
  2. 执行路径复用 run_task()；查询路径只调用 inspect_session()。若需要任务提交后立即返回 ID，则需另行设计后台任务调度和连接生命周期，不能直接照搬同步 CLI。
  3. 观察路径从已提交的记录读取进度；若选择 SSE，须确定事件标识与断线续接方式。现有 SQLite 记录不会自动变成事件流，断开观察连接也不等于取消运行。
  4. 按选择接入某一种扩展：工具适配继续返回 ToolResult；Hooks 要定义触发点和失败处理；编排要定义各任务的 ID、权限、取消和结果汇合。

1.3 当前表结构与尚不存在的数据

现有 五张表可以查询会话与执行进度，但当前没有用户或租户表、后台任务队列表、Worker 租约、取消状态、图节点或父子任务关联。events.sequence 是已有事件序号，尚无对外订阅或恢复协议。只有选定入口与编排方案后，才设计这些功能实际需要的字段及关联。

serve_tutorial.py 是独立的教程静态文件服务，只用于浏览 HTML 和源码，不调用 run_task()，也不提供 Agent HTTP API；它不创建这些业务表。

1.4 应用入口的目标

需要 Web 时先让 CLI / HTTP 共用应用用例；执行、查询与观察分开，断开 SSE 不等于取消任务。

2. 能力扩展

可复用的任务方法可以写成 Skills；在特定执行步骤触发逻辑可以用 Hooks；外部工具可以通过 MCP 接入；每种扩展仍需权限、预算与回执。

3. 编排分支

固定业务流程可考虑 Graph；独立上下文与分工可考虑子 Agent。先定义输入、权限、预算、取消和结果汇合。

4. 验收

与单 Agent 基线比较质量、费用、延迟和协调成本。能说明新增机制解决的真实问题，再决定是否保留这项扩展。
