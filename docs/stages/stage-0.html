阶段 0：跑通独立的最小 Agent Loop

打开 examples/00_plain_loop.py，从 run_agent() 开始阅读。

1. 问题起点：最小 Agent Loop 是如何运转的？

模型本身无法直接读取本地文件，只能根据每次请求传入的 messages 判断任务进展。一次完整的最小工具循环如下：

  • 用户：提出需要读取本地文件的任务。
  • 程序 → 模型：发送包含系统指令、用户问题与可用工具声明的 messages。
  • 模型 → 程序：返回工具调用请求（例如调用 read_file 读取 notes.txt）。
  • （系统动作：程序在本地执行 read_file，将读取到的真实文本或报错信息包装为 tool 消息，追加回 messages）
  • 程序 → 模型：携带追加了工具回执的 messages 发起下一轮请求。
  • 模型 → 程序：不再提出工具调用，直接返回最终回答，循环结束。

2. 核心实现：阅读 run_agent() 主循环

在 00_plain_loop.py 的 run_agent() 中，核心控制逻辑由三个关键机制组成：

  • 工具调用分支：若模型响应包含 tool_calls，则在本地执行对应函数，把结果追加进 messages 后进入下一轮循环。
  • 最终回答分支：若模型未提出工具调用且返回非空文本，则将其作为最终答案返回。
  • 步数上限与调用关联：通过 max_steps 防止死循环；通过 assistant.tool_calls[].id 与 tool.tool_call_id 一一配对，让模型在下一轮知道每份回执对应哪次调用。

2.1 当前函数与 SDK 类的关系

本阶段所有逻辑集中在单文件 00_plain_loop.py 中：main()、run_agent()、execute_tool() 和 read_file() 均为普通函数，直接使用 OpenAI SDK 客户端与字典格式的消息列表。

2.2 从启动到返回的执行流程

  1. 初始化：main() 加载环境变量配置，创建 OpenAI SDK 客户端，将任务描述、模型名与工作目录传给 run_agent()。
  2. 发起模型请求：run_agent() 初始化包含 system 和 user 的 messages 列表，调用 client.chat.completions.create()。
  3. 校验响应并分流：检查停止原因、拒答与工具调用类型，将正常的 assistant 消息加入 messages；若无工具调用且文本非空，直接返回最终答案。
  4. 执行本地工具：若有工具调用，execute_tool() 校验工具名、JSON 参数与路径后调用 read_file()。预期的读取失败（如文件不存在）转为错误回执，程序 Bug 则直接向上抛出。
  5. 回写回执并继续：将回执序列化为带 tool_call_id 的 tool 消息追加到 messages，进入下一轮请求；若达到 max_steps 仍未得出最终答案则报错停止，退出时关闭 SDK 客户端。

2.3 数据保存在哪里

TOOLS 是内存中的工具 Schema 列表，messages 是当次运行的消息列表，进程退出后自动释放。

3. 安装、配置与运行

需准备 Python 3.12+ 与 uv。参照 .env.example 配置有效的 API Key、HTTPS 端点与模型名称（环境变量优先于 .env 文件），在项目根目录执行：

项目根目录执行
uv sync --locked
uv run python examples/00_plain_loop.py

该命令会请求真实模型并消耗 Token（默认最多请求 4 次，关闭 SDK 自动重试）。

4. 工具实现与错误分流：execute_tool() 与 read_file()

在 00_plain_loop.py 中按 execute_tool() → read_file() 的顺序阅读，重点关注两层职责边界：

  • 入口参数校验（execute_tool()）：模型生成的工具参数属于不可信外部输入，必须在入口处校验工具名与 JSON 格式。
  • 资源边界控制（read_file()）：专注检查工作目录越界、符号链接、文件大小与 UTF-8 编码，便于独立测试与后续复用。
  • 预期失败与异常分流：文件不存在、路径越界等预期失败会转为结构化回执交回模型，给模型修正参数的机会；而模型连接失败、响应截断或代码 Bug 则立即中止循环，绝不伪装成成功或空内容。

5. 本地实验与自动化检查

可通过以下四个实验场景验证循环行为：

  1. 正常读取：读取 notes.txt，观察工具调用、真实文本回执与下一轮模型输入。
  2. 文件缺失反馈：请求不存在的文件，验证错误回执能正常传回模型。
  3. 安全边界拦截：测试越界路径、非 UTF-8 文件或超大文件，验证工具拒绝读取。
  4. 步数上限保护：让本地测试响应持续请求工具，验证达到 max_steps 时循环准确报错停止。
不请求外部模型的本地检查
uv run pytest
uv run ruff check learn_agent examples scripts tests
uv run mypy
uv run python scripts/check_docs.py

本地测试通过本机 HTTP 服务与真实临时文件校验 SDK 协议与控制流；真实模型的工具选择表现则通过运行第 3 节的示例观察。

6. 期望达到的效果

  • 调用链路清晰：能在源码中准确定位发送模型请求、执行本地文件读取、将回执追加回 messages 的具体代码行。
  • 结果关联准确：每次工具执行结果都通过 tool_call_id 与模型发起的调用精确配对。
  • 停止与错误边界明确：能区分正常给出最终回答、预期工具失败回传模型、以及达到 max_steps 报错停止三种路径。
