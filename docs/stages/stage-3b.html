阶段 3B：上下文管理与预算

本页是后续设计，尚未实现。当前 Runner 只发送本次任务内的消息，不跨调用加载历史，也不做输入预算检查或裁剪。会话与记录见 3A 的待实现设计。

1. 目标与完成标准

对话变长后，Context Manager 负责选择本次模型输入并检查大小：能说明保留和省略了什么，保持工具调用与回执配对；必需内容本身超限时明确停止，裁剪不删除原始记录。可先用内存消息验证，不依赖数据库。

2. 按实际问题选方案

方案适用情形代价
按完整任务裁剪优先保留近期对话可能漏掉早期要求，调用与回执须一起保留
大段结果另存与预览文件或日志占用过大需要能重新读取原文，说明版本与截断范围
摘要与近期原文需要保留较长任务脉络摘要可能失真，模型摘要增加调用与耗时

字节计数容易验证，但不等于模型的 Token 计数；预算单位和策略应由实际失败决定。其他方案与取舍见 Context Manager 通用教程。

3. 接入位置

当前请求由系统指令、本次任务消息、工具声明和输出上限组成。未来接入持久记录后，历史重建与本轮输入选择仍应分别处理；见 3A 的查询设计。

未来在 run_agent() 构造 ModelRequest 前增加输入选择，接口尚未确定。记录层保留原始材料，Model 负责协议转换，Policy 仍决定工具权限。

  1. Runner 收集历史、系统指令、当前消息和工具声明。
  2. 待实现的选择步骤保留必要内容，检查配对与预算；无法满足预算就停止。
  3. 通过后返回 ModelRequest 与选择说明，先保存请求，再调用模型。

当前没有会话数据库或输入预算记录。未来是否保留实际请求和选择说明，待实现时按验证需求决定。

4. 实现后怎样验证

覆盖刚好达到预算、完整旧任务被省略、多工具回执、必需内容超限、原生续接数据保留等情况。接入后确认：保存的请求与实际发送内容一致，裁剪不删除历史，预算检查失败时没有发出模型请求。

这些是后续验收要求，当前没有对应运行命令。模型摘要需要另行验证质量与 API 用量。
