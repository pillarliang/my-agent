当前最小骨架与未来模块蓝图

阶段 0 的单文件 Loop 位于 examples/00_plain_loop.py；阶段 1 已通过工具与模型接口接入 learn_agent/runner.py。下方先看当前执行流程，再看未来蓝图。

1. 阶段 0 的单文件执行主线

图中 Loop 对应 run_agent，模型 SDK 对应实际 API 请求；execute_tool 是工具入口，内部委托 read_file 读取文件。消息和工具定义由 Loop 传入 SDK，工具回执回到 Loop 后进入下一轮。

2. 阶段 1 的 Tools 接口与执行流程

应用创建 ToolRegistry 时直接传入工作目录与 Policy；Loop 依赖 ToolExecutor。注册表统一授权，文件执行函数接收参数、工作目录与已批准的动作。具体学习顺序见阶段 1。

3. 阶段 3A 拟接入的记录与历史读取

当前 Runner 用系统指令、本次任务消息与工具声明构造 ModelRequest，不读取历史或写入数据库。持久记录与续接仍是阶段 3A 的待实现设计。

4. 完整 Harness 的参考蓝图

未来参考，尚未实现。按任务需要逐步增加配置、Context、Policy、存储与检查器。图中多个名为 Runner 的节点代表循环中的不同步骤；不要求拆成独立服务。

模块职责见系统地图；通用教程分为应用配置、Harness 核心和按需扩展。最小版本无需把蓝图全部实现。
