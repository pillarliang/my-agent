1. 核心术语

术语描述职责与数据含义，不表示阶段 0 已定义同名 Python 类。阶段 0 使用 SDK 字典消息；阶段 1 的 Runner 使用项目内部统一的消息格式、ModelRequest 与 ModelResponse，工具调用使用 ToolCall、ToolResult 与 ToolExecutor。阶段 2 已实现 Policy；阶段 3A 已实现 Session、Run 与 Step；Context 管理尚未实现。Checkpoint（检查点）与 outcome（任务结果的验收结论）属于后续设计概念。

  • Agent：使用模型选择动作，并根据真实反馈继续执行的系统。
  • Harness：管理模型输入、工具、状态、权限与生命周期的运行系统。
  • Framework：用于构建系统的一组抽象和组件。
  • Agent Loop：一次 Run 中反复请求模型与执行工具的控制流。
  • 外层任务循环：反复启动、唤醒或评估 Run 的机制。
  • Graph：用节点、边与状态表达的控制流。
  • Session：把同一段对话中的连续任务组织在一起的会话；本项目中一个 Session 绑定一个工作目录。
  • Run：处理一个用户请求的过程。
  • Step：一次模型请求，以及根据该响应执行的工具调用与返回结果。
  • ToolCall：模型提出的工具名称、参数和调用 ID。
  • Invocation：一次逻辑工具调用。恢复或重试时用固定 ID 识别它，避免把同一动作当成新的动作重复执行。
  • Attempt：对一次 Invocation 的某次实际执行尝试；重试会产生新的 Attempt。
  • ToolResult：工具实际返回的内容、状态或错误，并带有对应调用的 ID。
  • Transcript：按顺序保存的完整消息与工具交互。
  • Context：本次实际发给模型的指令、消息、材料和工具定义。
  • Continuation data：模型服务要求在后续请求中继续携带的协议数据，例如响应中的推理项或加密内容。适配器负责解释，Runner 负责保存与传递。
  • Projection：从原始记录中生成某种用途的数据，例如供界面查询的状态或本次发给模型的消息；它不改变原始记录。
  • Idempotency（幂等）：对同一逻辑操作重复请求，不会产生额外结果。例如重试创建报告时，仍返回首次创建的报告，而不再创建一份。
  • Memory：经选择保存、供以后复用的知识。
  • Artifact：任务生成或使用的文件、报告、日志等结果。
  • Event：对关键执行步骤的记录，例如开始请求模型、工具返回结果或运行结束。
  • Checkpoint（检查点）：保存某个执行时刻的状态，以便之后从已确认的步骤继续。
  • Receipt：执行端保存的操作结果，可用于核对动作是否成功。
  • Policy：根据调用者、动作、资源和授权作出决策的规则。
  • Sandbox：限制实际执行环境可访问资源的隔离机制。
  • Eval：用一组任务比较系统行为与质量的过程。

下面是本项目采用的工作定义，用于讨论职责与实现。它们不代表行业已经形成统一、互斥的分层标准。

Harness 是包围模型的运行系统，负责输入组织、动作权限、状态记录、停止条件和错误处理。Agent Loop 则是其中的一段控制流，重复执行“构建输入 → 调用模型 → 执行工具 → 接收结果”。

外层任务循环负责重复启动或唤醒 Agent，例如在 CI 失败后启动诊断。它与一个 Run 内的模型循环处在不同范围，设计调度器时需要说明触发、等待和停止分别由谁负责。

Graph 用节点、边和状态转移表达控制流。节点既可以是普通函数或人工审批，也可以运行完整 Agent Loop；一个 Graph 可以只包含一个 Agent，也可以组织多个 Agent，因此 Graph 和 Loop 可以组合使用。

Framework 提供构建系统所需的组件和抽象，同一个产品也可以同时提供 Harness。理解产品时，可以分别问它提供了哪些开发组件、哪些运行约束，而不必强行把它归入单一类别。

Anthropic 的基础模式文章区分预定义工作流与由模型动态选择动作的 Agent。本文沿用这一思路，再单独讨论运行时需要补充的权限、状态和预算约束。

2. 动作被拒绝与循环结束

动作被拒绝：Policy 返回不允许，工具不执行这次操作，Runner 收到 policy_denied 回执后交给模型。

循环结束：Runner 返回 RunResult，包含模型回答与本次工具记录。模型的回答不能代替工具实际执行的回执。

3. 图的阅读方法

本教程直接在 HTML 正文中呈现图示、解释、示例与练习。复用图示在 assets/diagrams/ 中各自维护一个 SVG，相关章节引用同一文件；专属于章节的简图也可以直接写在正文中。

箭头含义以每张图的图例和标签为准：流程图的实线表示标注的调用或数据传递，虚线可能表示可选扩展或约束；时序图的虚线通常表示返回。依赖图中的箭头表示依赖方向，不能直接当作运行时调用顺序。每张图必须说明阶段 0 实现、通用机制或未来方案，不能从目标蓝图推断仓库已有对应实现。
