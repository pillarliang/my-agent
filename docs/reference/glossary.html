1. 核心术语对照

以下术语用于统一界定系统职责与数据边界（不要求代码中必须存在同名类；不同开源项目的粒度差异可对照 Session / Turn / Step 源码对照表）：

  • Agent：使用模型动态选择动作，并根据工具真实反馈继续执行的系统。
  • Harness：包围在模型外层的运行系统，负责管理模型输入、工具执行、状态持久化、权限拦截与停止条件。
  • Framework：用于构建 Agent 系统的一组开发组件与抽象接口。
  • Agent Loop：单次 Run 内部反复执行“构建输入 → 请求模型 → 执行工具 → 接收回执”的核心控制流。
  • 外层任务循环：在 Run 外部负责定时启动、按事件唤醒或触发评测的调度机制。
  • Graph：用显式节点、条件边与状态转移函数表达的工作流控制结构（节点内部也可以运行 Agent Loop）。
  • Session（会话）：把同一段多轮对话中的连续任务组织在一起的容器；本项目中一个 Session 绑定一个工作目录。
  • Run（单次运行）：从接收一个用户任务到循环结束（得出回答或因上限/异常停止）的完整执行过程。
  • Step（单步迭代）：一次模型请求，加上根据该次响应执行的全部工具调用与返回回执。
  • ToolCall（工具调用请求）：模型输出的待调用工具名称、参数字典与唯一调用 ID。
  • Invocation（逻辑调用）：一次具有业务含义的逻辑工具调用；在断点恢复或重试时用固定 ID 识别，防止把同一动作当成新动作重复执行。
  • Attempt（执行尝试）：对同一次逻辑 Invocation 的某次实际执行尝试（若发生重试，一次 Invocation 会对应多次 Attempt）。
  • ToolResult（工具回执）：工具执行后返回的真实结果、状态码或错误信息，并携带对应的 ToolCall ID。
  • Transcript（完整交互记录）：按发生顺序持久化保存的原始消息与工具交互全集。
  • Context（本轮模型输入）：单次调用模型前，经筛选和组装后实际发给模型的系统指令、历史消息、参考资料与工具定义。
  • Continuation data（协议续接数据）：模型服务要求在后续请求中原样传回的协议层数据（如推理项或加密状态），由适配器解析、Runner 保存与传递。
  • Projection（数据投影）：从原始记录（Transcript）派生出的特定视图（如发给模型的 Context 视图或供前端展示的会话摘要），生成过程不修改原始记录。
  • Idempotency（幂等性）：对同一逻辑操作重复发起请求不会产生重复副作用（例如重试创建报告时直接返回首次创建的报告，而不会生成两份文件）。
  • Memory（长期记忆）：经筛选保存、可跨会话复用的稳定事实与用户偏好。
  • Artifact（产物）：任务执行过程中生成或读取的文件、报告、长日志等实体数据。
  • Event（运行事件）：对关键执行节点的结构化记录（如发起模型请求、工具返回回执、运行结束）。
  • Checkpoint（检查点）：在固定执行边界保存的状态快照，支持中断后从最后一个已确认步骤安全恢复。
  • Receipt（操作回执）：执行端持久化保存的真实操作结果，用于恢复时核对外部动作是否已经生效。
  • Policy（权限策略）：在动作执行前，根据操作类型、目标资源与配置判定“允许”或“拒绝”的规则组件。
  • Sandbox（沙箱）：在操作系统或容器层面限制进程可访问文件系统、网络与系统资源的隔离机制。
  • Eval（评测）：使用固定任务集、初始快照与检查标准，量化对比系统行为与产物质量的过程。

易混概念辨析（参考 Anthropic Building Effective Agents）：

  • Harness vs Agent Loop：Agent Loop 是内部“请求模型 ↔ 执行工具”的循环控制流；Harness 则是包含 Loop 在内的完整运行底座（涵盖 Context 预算、Policy 权限、State 记录与异常恢复）。
  • Graph vs Agent Loop：两者并非二选一。Graph 定义确定的阶段流转，而 Graph 中的某个节点完全可以运行一个自主决策的 Agent Loop。

2. 核心状态区分：动作被拒 vs 循环结束

  • 动作被拒绝（policy_denied）：Policy 判定不允许执行该操作，底层工具根本不会运行；Runner 将拒绝回执传回给模型，由模型决定如何向用户解释或调整方案。
  • 循环结束（RunResult）：Runner 停止循环并返回包含模型最终文本与本轮工具回执列表的 RunResult；注意模型口头声称“已完成”不能替代真实的成功工具回执。

3. 架构图与时序图阅读指南

  • 实线与虚线含义：在流程图中，实线表示主调用或数据流向，虚线表示可选扩展或策略约束；在时序图中，实线表示发起调用或写入，虚线表示返回结果。
  • 依赖方向 vs 调用顺序：模块依赖图中的箭头表示“谁依赖谁的接口”，不能直接等同于运行时的先后调用顺序。
  • 区分“当前已实现”与“未来蓝图”：每张图均在标题或图注中标明属于“阶段 0–3 已实现流程”还是“未来扩展方案”，阅读时可随时对照源码核实。
