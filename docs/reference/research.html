以下资料按指定版本的源码提交或官方文档收录，供设计时对照。

核对日期：2026-10-18。本次研究服务于模块教程：解释实现机制、比较设计选择，并确定 Learn Agent 的学习顺序。它是有明确样本的研究，不是所有 Agent 产品和技术方案的完整目录，也没有对所列产品进行统一性能测试。

1. 证据怎样标注

源码核对表示阅读了下列提交中与结论相关的函数和调用位置，没有逐行审计整个仓库。官方文档表示页面在核对日公开描述了该行为，网页可能继续变化。本项目建议表示根据任务需求与限制提出的设计，不能归为某个产品的实际实现。

源码入口使用指向指定提交的链接，避免 main 更新后失去阅读依据。要复查行为，先读入口函数，再沿它的调用查找状态更新、失败分支和持久化位置；只看到一个类名，还不能确认它已接入默认执行流程。

2. 指定版本的源码样本

pi：小型循环与可扩展 Harness

样本提交为 9d2ec7ffabe927bfad2214c1cee25b6632a78dcf，提交日期 2026-08-13，来自本机已有仓库。本次没有把它更新到最新版，因此教程只将它作为固定实现样本。

  • agent-loop.ts：streamAssistantResponse、transformContext 与 convertToLlm 的顺序，以及工具串行、并行分派。
  • Harness compaction.ts：shouldCompact、findCutPoint、prepareCompaction 和摘要生成。
  • session/context.ts：buildSessionContext 将压缩记录和保留的近期消息整理成模型输入。
  • session-format.md：JSONL、父子条目、分支与格式兼容。

该快照同时存在较早的 coding-agent 实现和抽到 agent 包中的 Harness 实现。Context 教程以后一套为源码依据：新压缩条目包含 retainedTail；旧文档中的 firstKeptEntryId 是另一种保留方式，不能混写成同一数据结构。

Deep Agents：用中间件组合 Harness 的各项功能

样本提交为 97f856dcb08264ef78722a4687cab9133ec5fb7a，提交日期 2026-10-18。

  • graph.py：create_deep_agent 装配内置和自定义中间件、模型、后端与子 Agent。
  • summarization.py：compute_summarization_defaults、wrap_model_call，以及摘要事件、历史内容另存和输入预算。
  • filesystem.py：wrap_tool_call 拦截大结果，文件工具与后端分离。
  • memory.py：before_agent 加载配置的记忆文件，modify_request 修改本次请求。
  • skills.py 与 subagents.py：方法发现、子任务输入准备和结果返回。

AgentScope Java：工作区、上下文和执行状态

样本提交为 40a4a57ad79e82f8505572d3b195d0264ec7efcb，提交日期 2026-10-18。这里研究的是 Java 仓库的 v2 文档和 Harness，不是 AgentScope Python；两者 API 与默认配置不能互换。

  • context.md：指令、动态来源、材料选择、最终请求预算与诊断清单。
  • CompactionMiddleware.java：模型请求前的压缩处理与输入超限处理。
  • ConversationCompactor.java：旧工具结果裁剪、摘要与保持工具调用与返回结果配对。
  • memory.md、session-log.md 和 subagent.md：记忆处理流程、持久执行与子任务的官方设计说明。本次没有运行 Java 示例来验证恢复或分布式保证。
