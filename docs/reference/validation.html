本地检查与验证范围

本页列出项目的自动化检查命令，以及单元测试、本地协议测试与真实模型实验各自的覆盖边界。

1. 一键运行本地检查

在项目根目录依次执行（无需配置外部 API Key）
uv run ruff check learn_agent examples scripts tests
uv run ruff format --check learn_agent examples scripts tests
uv run mypy
uv run pytest
uv run python scripts/check_docs.py

2. 各测试模块覆盖的行为

  • 阶段 0 单文件闭环（test_plain_loop.py）：验证脚本零内部包依赖、工作区路径限制以及多轮工具调用闭环。
  • Tools 注册与文件边界（test_tools.py）：覆盖重复注册冲突、Schema 生成与严格参数校验、工作目录越界与符号链接拦截、文本搜索与大输出截断，以及预期业务失败与程序 Bug 的异常分流。
  • Policy 权限控制（test_policy.py）：覆盖只读、允许新建但禁止覆盖等策略对真实文件操作的拦截效果。
  • Model 协议适配（test_models.py）：让真实 OpenAI SDK 请求本机 HTTP 测试服务，验证 Token 用量提取、停止原因映射、协议续接数据（continuation data）原样往返、端点混用拒绝以及超时/HTTP 错误转换。
  • Session 会话持久化（test_session.py）：覆盖关闭重开后记录可查、同会话多轮追问上下文延续、新会话相互隔离、失败运行片段过滤、JSONL 损坏检测、并发文件锁与只读查询零副作用（分步操作见阶段 3）。
  • Application 端到端装配（test_application.py）：覆盖自然语言任务入口、按配置装配工具与 Policy，以及指定会话 ID 的历史续接。
  • 真实模型端到端验证：本机固定 HTTP 响应仅用于验证程序逻辑与协议格式；在配置好 DashScope API 后运行通用入口（如 2026-10-20 实测验证），模型可自主调用 search_text 在 notes.txt 第 3 行定位 LEARN-42 并根据真实回执作答。
