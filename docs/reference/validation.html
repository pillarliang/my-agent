Loop / Runner：控制一次任务怎样继续和停止Model：适配模型服务与通信协议Context Manager：组织本次发给模型的内容Tools：执行模型提出的工具调用Policy：在执行前检查操作权限Session / State：管理会话与执行记录Quality：观测与评测

2. 已覆盖的行为

本地检查覆盖阶段 0 的独立性、文件访问与循环行为，以及 Tools 的注册冲突、Schema 与严格参数校验、资源与符号链接限制、搜索与截断、预期失败与程序错误分流、工具说明与实际分发一致、SDK 后续请求的消息格式和阶段 1 入口。模型检查还覆盖用量、停止原因、continuation 数据的保留与传递、端点混用拒绝与 HTTP / 连接 / 超时错误。应用检查还覆盖不提供文件名的自然语言任务、按配置注册工具，以及 Tools 与 Policy 的交互。案例见 test_application.py、test_policy.py、test_plain_loop.py、test_tools.py 与 test_models.py。

会话与持久记录目前没有实现或对应测试；后续验收要求在阶段 3A说明。当前应用测试检查独立调用的消息不自动混入前一次任务；Context 预算与真实模型连续任务表现也未验证。

SDK 请求只到本机 HTTP 测试服务；固定响应用于检查协议格式与程序流程，不能证明模型的理解和决策能力。真实模型可用性、任务质量与供应商端点需配置后单独运行示例观察。

真实示例验证（2026-10-20）：使用现有 DashScope 配置完成两次模型请求；模型调用 search_text，在 notes.txt 第 3 行找到 LEARN-42，并依据真实回执回答路径、行号和标记。这验证了该示例中模型请求、工具执行和结果反馈的完整过程，不代表其他模型、流式或任务质量已验证。
