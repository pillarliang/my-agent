# ADR 0001：保持可观察的最小边界

状态：已采用。日期：2026-10-18。

## 背景

项目希望让学习者从零看清 Agent Harness 的控制流与数据边界，同时得到一个能实际运行的系统。通用编程工具、自动恢复和分布式服务会显著扩大首版范围，因此先用明确的小任务建立理解基础。

## 决定

1. 使用一个 Python 包与 uv。先不采用 Agent Framework。
2. 使用同步 Loop。先不采用流式、异步队列和 Graph 运行时。
3. 通过 Model Protocol 隔离 SDK。
4. 工具参数采用 Pydantic，定义与校验共用类型。
5. 使用三个专用文件工具。默认只读，写授权只允许新建。
6. 通过 SQLite 保存完整消息和元数据事件。
7. Context 只裁剪旧完整轮次。当前链放不下时明确停止。
8. 验证器独立于模型，首版只做文件文字检查。
9. 自动恢复、长期记忆和扩展加载留到后续阶段。

## 代价

同步 I/O 无法提供严格的进程抢占，字节保护也不能精确限制模型窗口；按整轮裁剪会丢失早期信息，而新建文件和数据库记录之间仍存在故障窗口。这些取舍使首版容易观察，但后续增加恢复和执行隔离时，需要分别补齐相应协议。

## 重新评估条件

长任务经常发生上下文溢出时，应增加摘要与计数器；需要执行任意代码时，应先增加沙箱与执行端口。若要跨进程继续，就先设计调用回执和对账；若要持续协作，就先明确父子身份、预算和取消传播。

修改边界时，请更新本记录、对应教程和失败测试。
