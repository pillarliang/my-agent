# ADR 0002：共用应用服务，增加本地 Web UI

状态：已采用。日期：2026-10-18。

## 背景

CLI 原先直接装配 Runner，新增的 Web UI 也需要聊天、进度和历史。将共同用例提取到应用服务，可以让两个入口复用同一个循环；现有 SQLite 事件则能继续作为进度观察与断线补读的来源。

## 决定

1. 把共同装配与执行用例提取到 `AgentService`。
2. CLI 与 FastAPI 都调用该应用层。
3. 浏览器使用原生 HTML、CSS 和 JavaScript，不增加前端构建链。
4. 使用 POST 提交任务，使用 SSE 观察持久事件。
5. 同步 Runner 通过 `asyncio.to_thread` 执行。
6. 每个用例创建本线程的 SQLite 连接，不跨线程共享连接。
7. 默认只绑定回环地址，模型与权限由服务启动参数决定。

## 代价

工作线程与进程内 Task 便于复用同步 Runner，但无法提供独立沙箱、可靠强制终止或崩溃后的持久任务恢复。数据库补读适合当前本地低并发场景，后续负载增加时还需要评估事件分发方式；首版也未提供逐 Token 输出、取消按钮或多租户登录。

## 重新评估条件

需要强制取消或执行不可信代码时，应引入独立 Worker；需要高并发广播时，再评估事件订阅与分发层。跨主机运行还需要持久队列、幂等派发和恢复协议，不能只扩展后台 Task 集合。
