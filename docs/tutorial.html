逐步建成什么样的系统

先看职责，再按阶段实现。下列状态描述当前代码；图中按职责划分模块，不要求每一项都有独立目录或服务。

  • 应用与行为配置
    • 用户入口、任务目标、指令与工具选择当前：CLI 入口；模型连接配置由 LLMService 内部管理
  • Harness 核心
    • Loop / Runner：推进、预算、停止与汇总。已实现最小循环与请求次数上限
    • Model / LLMService：统一模型调用，隔离协议与连接配置。已实现单端点、非流式调用
    • Context Manager：选择、组织和计量本轮输入。后续模块，尚未实现输入选择、预算或裁剪
    • Tools：能力声明、校验、分发与真实回执。已实现 list_files、read_file、search_text 与受控 write_file
    • Policy：授权、资源约束与按需审批。支持读取、新建与覆盖判断；默认禁止覆盖
    • Session / State：执行过程、历史、事件与持久记录。已实现 SQLite 会话、运行、步骤、消息与事件；未实现自动恢复
    • Quality：进度、追踪与评测。已有事件记录与本地检查，独立观测／评测模块未实现
  • 按需求增加的能力
    • 长任务与知识复用：计划、压缩、检索、记忆。
    • 可靠执行与隔离：调度、恢复、Worker、沙箱。
    • 扩展与编排：Skills、MCP、Hooks、Graph、多 Agent、UI。
  • 外部资源
    • 模型服务、工作区、数据库与外部 API。当前接入模型服务、本地工作区与 SQLite

应用与行为配置
