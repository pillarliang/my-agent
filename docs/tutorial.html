逐步建成什么样的系统

按职责划分系统边界，先明确每个模块解决什么问题，再按阶段逐步落地代码：

  • 应用与行为配置
    • 用户入口、任务目标、系统指令与工具集配置已实现：CLI 命令行入口；模型连接配置由 LLMService 内部管理
  • Harness 核心
    • Loop / Runner：推进循环、控制步数上限、汇总运行结果。已实现：最小自主工具循环与最大步数限制
    • Model / LLMService：统一模型调用接口，隔离 SDK 协议与凭证管理。已实现：单端点非流式调用与协议转换
    • Tools：管理能力声明、参数校验、函数分发与真实回执。已实现：list_files、read_file、search_text 与受控 write_file
    • Policy：在工具执行前检查操作权限与资源边界。已实现：区分读取、新建与覆盖；默认允许新建、禁止覆盖
    • Session / State：持久化保存会话记录，支撑历史查询与多轮续接。已实现：单会话 JSONL 存储、Turn 边界、历史查询与上下文还原
    • Context Manager：在预算内筛选并组装本轮发给模型的上下文。已实现：输入估算、必需历史保护与按完整任务裁剪
    • Observability：运行时全链路观测与追踪。支持接入 Langfuse 追踪与可视化分析
    • Evaluation：离线任务验收、沙箱隔离断言与基准评测。已有本地测试与协议测试；支持接入 Inspect AI 与沙箱
  • 进阶扩展模块
    • Memory：跨会话知识沉淀、增删改查与分层检索。已实现：阶段 5 项目记忆 MVP (MEMORY.md)
    • Recovery：中断定位、异常分级、检查点与安全恢复。
    • Extensions：Skills、Hooks 与 MCP 外部工具标准化集成。
    • Orchestration：多 Agent 协作、子任务委派与 Graph 编排。
  • 外部资源
    • 模型服务、本地工作区、存储介质与外部 API。当前已接入：模型服务、本地工作区与 JSONL 会话文件

应用与用户入口

管理用户从哪里提交任务、注入什么系统指令与工具集，以及如何展示结果。入口函数 main() 接收参数并配置工作区与 Policy；run_task() 组装工具注册表与模型服务并启动 Runner。
