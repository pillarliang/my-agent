Quality Assurance · Local Automated Checks & Real-Model Verification

Local Checks & Verification Scope

This page lists the project's automated check commands and the coverage boundaries of unit tests, local protocol tests, and live model experiments.

1. Run Local Checks in One Go

Run sequentially from the repository root (no external API key required)
uv run ruff check learn_agent examples scripts tests
uv run ruff format --check learn_agent examples scripts tests
uv run mypy
uv run pytest
uv run python scripts/check_docs.py

2. Behaviors Covered by Each Test Module

  • Stage 0 single-file loop (test_plain_loop.py): Verifies zero internal package dependencies, workspace path confinement, and the multi-turn tool-call loop.
  • Tool registration & file boundaries (test_tools.py): Covers duplicate registration conflicts, schema generation and strict argument validation, workspace traversal and symlink interception, text search and oversized output truncation, and separating expected domain failures from programming bugs.
  • Policy permission control (test_policy.py): Covers how read-only and create-without-overwrite policies intercept real file operations.
  • Model protocol adaptation (test_models.py): Points the real OpenAI SDK at a local HTTP test server to verify token usage extraction, stop-reason mapping, round-trip preservation of protocol continuation data, rejection of mixed endpoints, and timeout/HTTP error translation.
  • Session persistence (test_session.py): Covers inspecting records after process restart, multi-turn follow-up context continuation within the same session, isolation across separate sessions, filtering of failed run fragments, JSONL corruption detection, concurrent file locks, and zero side effects on read-only queries (see Stage 3 for step-by-step commands).
  • Application end-to-end wiring (test_application.py): Covers the natural-language task entry point, configuring tools and Policy per task, and resuming history with a specified session ID.
  • Live model end-to-end verification: Local canned HTTP responses only verify program logic and wire formatting; when configured with the DashScope API and run via the general entry point (verified live on 2026-10-20), the model autonomously calls search_text, locates LEARN-42 on line 3 of notes.txt, and answers from the real tool receipt.
