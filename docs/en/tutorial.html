Learning Path: Expanding Step by Step from a Standalone Loop

Each core module first delivers a Minimum Viable Product (MVP) that plugs into the existing closed loop and can be verified independently—completing the end-to-end main path before making targeted improvements based on real task bottlenecks.

How Stages Map to the Module Responsibility Map
  1. Stage 0 · Minimal Loop: Run the closed loop of "model request → tool execution → result feedback" in a single file.
  2. Stage 1 · Module Split: Extract Tools and Model modules so Runner calls them through unified protocol interfaces.
  3. Stage 2 · Permission Control: Connect Policy to intercept dangerous actions like overwriting existing files before execution.
  4. Stage 3 · Sessions & Records: Persist dialogue and tool records as JSONL to support history queries and multi-turn follow-ups.
  5. Stage 4 · Context Management & Budgets: Select what goes into the current model request within budget as history grows.
  6. Stage 5 · Project Memory: Read manually maintained project knowledge for new sessions and include it in context budgets.
  7. Stage 6 · Long-Task Mechanisms: Select result previews, history summaries, retrieval, or further memory designs based on real bottlenecks.
  8. Stage 7 · Reliable Execution: Handle state reconciliation and safe resumption after process interruption.
  9. Stage 8 · Extensions & Orchestration: Connect HTTP entry points, Skills, Hooks, MCP, and multi-agent collaboration on demand.
