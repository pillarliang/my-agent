# 教程补充与写作规范

本规范适用于本项目教程的新增、补充与修改，也适用于代码变更后的教程同步。贡献者与代码助手均应遵循。

## 读者与目标

面向第一次从零实现 Agent 的读者。让读者理解模块解决的问题、模块之间怎样协作，并能沿源码完成一个可运行、可验证的小版本。

从 `examples/00_plain_loop.py` 的独立闭环逐步扩展。每次只讲当前阶段所需，明确区分已实现、后续实现与可选方案。

## 章节分工

- **模块通用教程**：说明是什么、为什么需要、有什么用，提炼核心抽象，解释黑盒交互接口。
- **阶段教程**：说明本轮范围、实现与源码阅读顺序、运行方式和验收条件；通过链接引用通用原理。
- **系统职责地图**：展示模块分工和当前进度。按应用与行为配置、Harness 核心、按需扩展、外部资源组织，与学习阶段分开。

Harness 核心包含 Runner、Model、Context Manager、Tools、Policy、Session / State、Quality。地图中的状态必须与源码一致。

## 模块讲解顺序

1. **核心问题与抽象**：先用直白语言解释模块是什么、为什么需要、有什么用，再引出最少的核心抽象。配一个贴近当前项目的例子，说明缺少这项机制会遇到什么问题，以及加入后的行为。
2. **黑盒交互接口**：把模块与 Runner 或相邻模块视为黑盒，用图标明操作、输入、输出与方向。说明谁发起调用、谁作决定、谁实际执行，以及失败如何返回。
3. **实现顺序与源码入口**：链接真实文件和关键函数，让读者沿一次调用阅读。具体实现步骤放在对应阶段，避免两处重复。
4. **最小运行与验收**：给出可执行命令、观察位置和预期结果，同时覆盖成功与有代表性的失败。

例如 Policy：先解释它用规则约束 Agent 的动作，再用“只允许新建指定报告”说明授权的作用，最后引出保存规则的 `Policy` 与作出决定的 `PolicyService`。同时讲清授权决定、工具执行和产物验收各自回答的问题。

## 内容与表达

- 使用简洁中文和具体例子，先解释概念再引入名称；不要直接从类名或功能清单开始。
- 精简重复内容，保留原理、设计动机、关键数据关系、失败语义与实验预期；不能把教程缩成源码链接目录。
- 实现只在源码中维护。教程不复制已有函数，不用伪代码、职责表、字段表或长段文字复述源码。
- 不写旧版本迁移过程和历史实现对照，不反复列举尚未实现的功能。较长的可选方案放入折叠区，不作为起步必读。
- 区分参数合法、动作获准、执行成功和任务通过验收；模型文字不能代替真实回执与实际产物检查。

## 文件与维护方式

教程唯一正文入口是 [tutorial.html](tutorial.html)，直接维护其中的 HTML 与内联 SVG，让图、解释和练习放在一起。不增加文档生成流水线或另一份教程实现。

[README](../README.md) 保留项目入口、阅读导航与运行方式，具体教学内容放回教程。本文件只维护写作规范。

## 提交前检查

- 代码变化后，同步相关章节的接口名称、源码链接、行为说明、图示和职责地图状态。
- 运行命令可复制执行，验收说明包含真实文件或回执的观察方式。
- 明确区分本地程序与协议测试、真实模型表现；真实 API 调用说明用量，没有运行的实验不写成已验证。
- 检查 HTML 结构、锚点与 SVG 引用，确认新增内容易读且没有与相邻章节重复。

在项目根目录运行文档检查；代码检查按 [README](../README.md#本地检查) 执行：

```sh
uv run python scripts/check_docs.py
```

该命令只检查链接、围栏和 HTML 引用，内容准确性与图示可读性仍需人工核对。
