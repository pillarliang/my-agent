# 07. 术语与写作约定

## 1. 以中文阅读体验为准

本项目的主要教程使用中文，以自然、连贯、容易理解的技术表达为目标。解释一个概念时，可以在同一段中说明它的作用、原因和例子，不要求一句话一行，也不为追求短句而拆散完整的意思。

ASD-STE100 仅作为技术写作的参考，不是项目文档必须遵守的规范。我们保留术语一致、动作明确、结果可检查等有帮助的原则；句子长度、段落组织和说明深度则以读者能否顺畅理解为准。另有一份[英文操作简表](STE-QUICKSTART.en.md)，可作为运行参考，但不作严格合规声明。

## 2. 如何组织说明

正文按一个主题一个段落组织，相关句子放在同一段中，让读者能够连续理解概念与因果关系。需要开始新的主题、切换说明角度或展示示例时，再另起一段；源文件也按段落换行，不逐句断行。段落过长时应按内容拆分，不能只是把零散短句机械拼在一起。

写作时遵循以下约定：

- **先解释作用，再介绍细节。** 新模块先说明它解决什么问题，以及它与相邻模块的关系，再展开接口和实现。术语在首次出现时给出必要解释，避免读者只能靠名称猜测。
- **术语保持一致。** 同一个词尽量只表示一个概念；需要区分 Session、Run 和 Step 时，明确各自的范围。代码中的标识符保留原名，方便读者定位实现。
- **步骤与解释分开组织。** 有先后依赖的操作使用编号列表，命令给出执行目录和预期结果；原理、背景和取舍使用连贯段落。多个入口或方案之间，应说明是任选、递进还是有前置依赖。
- **比较方案时说明选择依据。** 交代各方案的用途、代价、适用条件和常见失败方式，而不是只罗列名词。新方案应能对应到当前模块和后续改动位置。
- **如实说明实现状态。** 区分当前代码、后续设计和未验证内容，限制要说明具体后果。不要仅凭“生产级”等标签表达质量，也不要把循环结束等同于任务验收通过。
- **图表服务于理解。** 控制流、数据关系和模块边界适合用图表达；单一事实或一条简单操作可以直接说明。图旁应交代它描述的是当前实现还是目标设计。

本地文档检查器只检查链接路径和代码围栏，不检查表达质量、技术内容或完整的 Mermaid 语法。文档是否清楚，仍需要结合代码、运行结果和实际阅读体验审阅。

## 3. 核心术语

- **Agent**：使用模型选择动作，并根据真实反馈继续执行的系统。
- **Harness**：管理模型输入、工具、状态、权限与生命周期的运行系统。
- **Framework**：用于构建系统的一组抽象和组件。
- **Agent Loop**：一次 Run 中反复请求模型与执行工具的控制流。
- **外层任务循环**：反复启动、唤醒或评估 Run 的机制。
- **Graph**：用节点、边与状态表达的控制流。
- **Session**：连续交互的会话身份。
- **Run**：处理一个用户请求的过程。
- **Step**：一次模型请求与该响应提出的工具批次。
- **ToolCall**：模型提出的工具名称、参数和调用 ID。
- **Invocation**：后续执行账本中一个稳定逻辑动作的身份。
- **Attempt**：一次实际派发尝试。
- **ToolResult**：程序返回的工具执行观察。
- **Transcript**：按顺序保存的完整消息与工具交互。
- **Context**：某次模型请求实际可见的输入视图。
- **Memory**：经选择保存、供以后复用的知识。
- **Artifact**：工作区或产物库中的外部交付物。
- **Event**：关键运行边界的记录。
- **Checkpoint**：用于定位执行位置的状态快照。
- **Receipt**：执行端保存的真实执行回执。
- **Policy**：根据身份、动作、资源和授权作出决策的规则。
- **Sandbox**：限制实际执行环境可访问资源的隔离机制。
- **Verifier**：检查当前结果是否满足指定条件的组件。
- **Eval**：用一组任务比较系统行为与质量的过程。

## 4. 三个容易混淆的状态

**未检查（unchecked）**表示没有运行任务检查器，所以不能从这个状态推断验证通过或失败。例如，一次聊天正常结束，但未配置文件检查器时，验证结论仍然是未检查。

**未知（unknown）**表示无法确认某个动作的真实效果。例如，在带外部副作用的后续设计中，连接中断不一定意味着动作没有发生，因此不能将“未知”直接视为“失败，可以重试”。

**循环已结束（completed）**只描述执行引擎正常结束，不用“已完成”表示任务验收。面向用户使用 `outcome` 的“已通过指定检查”“验收检查未通过”“结果未验证”或“执行未完成”，并展示证据和检查范围，模型文字作为说明。

## 5. 图的阅读方法

实线箭头通常表示控制流或明确的数据流，虚线通常表示扩展、约束或事件记录。每张图周围的说明会交代它描述的是当前代码还是后续目标；依赖图中的箭头表示导入方向，不能直接当作运行时调用顺序。
